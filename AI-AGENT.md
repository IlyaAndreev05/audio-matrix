# Editing Audio Matrix configuration

- `~/.config/audio-matrix/config.yaml` is the only persistent settings source. Do not store settings in a database or edit generated/runtime PipeWire IDs into the file.
- Validate changes with `./gradlew run --args="--validate-config /path/to/config.yaml"`.
- Keep stable device IDs and selectors; PipeWire object IDs are temporary. Supported device selector kinds are `name_equals`, `name_contains`, and `description_contains`. A device `name` is a display alias. Profile `default_output` and route `to` values may reference stable device IDs; preserve those IDs when changing a selector.
- Device roles are explicit optional YAML values: `haptic_output`, `subwoofer`, `speaker`/`speakers`, or generic `output` for outputs; `input`, `microphone`, `accelerometer`, or `source` for inputs. A missing role is unassigned. Do not infer or assign `haptic_output` from a device name. Specialized modes filter final routes: Haptic requires every source path to originate exclusively from an `effects` bus and the sink to be `haptic_output`; Subwoofer requires the final branch bus/output to be `subwoofer`, accepts only music or subwoofer roots, and warns if any active path lacks a low-pass; Speaker requires a `speaker`/`speakers` output. Bus roles are `general`, `music`, `effects`, and `subwoofer`.
- `engine.transition_ms` controls a linear fade on Audio Matrix-owned route playback nodes when rebuilding/clearing the graph; valid values are integers from 0 to 1000 ms. This only smooths the software route gain and does not limit amplifier or transducer power.
- An application, bus, route, or output device may reference an EQ chain as `dsp.route_chains.<id>` with `filters_ref`. The Applications page assigns app chains; each matching active stream receives its own filter node before its bus. An output device's shared chain runs once after route branches to that sink are mixed. Filters are shared config records, so edit a chain only when all its references should change.
- High-pass and low-pass filters may set `slope_db_oct` to 6, 12, 18, 24, 36, or 48; the default is 12. Higher orders render as cascaded Butterworth sections. The `q` setting applies to the 12 dB/oct form; omit it for higher/lower orders unless preserving external metadata.
- The app checks the on-disk fingerprint before each atomic replacement. If an editor changed the file concurrently, resolve the conflict instead of overwriting it.
- Never add fictional calibration measurements. Measurement WAV/CSV files are stored separately and referenced from YAML.
